# Repository Guidelines

## Notes before writing your code
Don't create the UI easily looks like generated by AI agent.

## Project Structure & Module Organization
- `client/` hosts the React + TypeScript UI; keep panes in `src/components`, network logic in `src/services`, and state in `src/store`.
- `server/` powers the Express + Socket.io API; grow modules under `src/services`, read `.env` for ports, and keep generated artifacts in `temp/`.
- `shared/` stores cross-cutting contracts such as TypeScript types, socket event enums, and utility constants shared by both runtimes.
- `docs/` contains the authoritative architecture notes; update diagrams and narratives whenever flows or panels change.

## Build, Test, and Development Commands
- `cd client && npm install && npm run dev` starts the Vite dev server on `5173`.
- `cd server && npm install && npm run dev` runs the API on `PORT` (default `4000`).
- Ensure `npm run build` and `npm run lint` exist in each workspace and stay green before pushing.

## Coding Style & Naming Conventions
- TypeScript is strict by default—declare explicit return types, avoid implicit `any`, and narrow unions decisively.
- Components and classes use PascalCase; hooks, services, and utilities stick to camelCase; environment variables stay SCREAMING_SNAKE_CASE.
- Prefer functional React components with typed props from `shared/`; isolate side effects inside `useEffect`.
- Format with two-space indentation and Prettier defaults, grouping imports as external, shared, then local modules.

## Testing Guidelines
- Place frontend tests in `client/src/__tests__` using Vitest + React Testing Library with filenames like `Pane.test.tsx`.
- Back-end tests belong in `server/src/__tests__`; mock the R child process and Claude API rather than hitting real services.
- Capture coverage reports (target ≥80% on touched files) and attach summaries to every pull request.

## Commit & Pull Request Guidelines
- Follow the imperative, lower-case commit style already in history (`add tsconfig`); optional prefixes such as `feat:` help scanning.
- Every PR needs a short problem statement, concise change list, and test or build evidence.
- Link issues, update `.env.example` when env vars move, and mention doc or schema changes explicitly.
- Rebase on `main` before requesting review and ensure dev, build, lint, and tests pass locally.

## Security & Configuration Tips
- Keep real secrets in untracked `.env.local` files; the committed `.env` values should be placeholders only.
- Confirm `R_PATH` resolves to the intended R runtime and document overrides in PR notes.
- Clear `server/temp/` before shipping releases so stray plots or logs never leak.

## Bash Command Permissions for AI Agents
When working with this repository, AI agents have permission to execute the following commands without asking:

### Development Commands (Always Allowed)
- `cargo check --workspace` - Check Rust compilation
- `cargo build --workspace` - Build all Rust crates
- `cargo run -p <package>` - Run specific Rust package
- `cargo tauri dev` - Run Tauri desktop app in dev mode
- `npm run dev` - Run development server
- `npm run build` - Build production bundle
- `npm test` - Run tests
- `npm install` - Install dependencies

### Git Commands (Read-Only Always Allowed)
- `git status` - Check repository status
- `git log` - View commit history
- `git diff` - View changes
- `git branch` - List branches

### Git Commands (Write Operations - Allowed but NO force options)
- `git add <files>` - Stage files for commit
- `git commit -m "message"` - Create commits (simple messages only, no Co-Authored-By required)
- `git push` - Push to remote (NEVER use --force)

### System Commands (Always Allowed)
- `ls`, `pwd`, `cat` - File system navigation and reading
- `which <command>` - Check command availability
- `lsof -i :<port>` - Check port usage
- `mkdir -p <path>` - Create directories
- `rm -rf <path>` - Remove files/directories (use with caution)

### File Operations (Always Allowed)
- Read any file in the project directory
- Edit configuration files: `.tsx`, `.ts`, `.js`, `.json`, `.toml`, `.md`
- Create/edit Rust files: `.rs`, `Cargo.toml`
- Create/edit documentation: `.md` files

### Configuration File Creation (Allowed)
- `~/.reprod/auth.json` - Application configuration (API keys, R path)
  ```json
  {
    "anthropic_api_key": null,
    "r_path": "Rscript"
  }
  ```

### Restricted Operations (NEVER Allowed)
- Git commands with `--force`, `--hard`, `--amend` (unless explicitly requested)
- System-wide installations (use project-local only)
- Modifying system files outside project directory
- Destructive operations without confirmation
